## 一、你负责的系统（原理速通 · 要能讲因果）

**1. 硬件都有什么，各干什么**

| 零件 | 作用 | 接在哪 |
|---|---|---|
| ESP32 | 大脑（本地决策 + 控制执行器） | 主控 |
| 土壤湿度传感器 | 测土干湿 | GPIO34（ADC） |
| DHT11 | 测温湿度 | GPIO4 |
| 继电器×2 | 电子开关，控水泵 / 补光灯 | GPIO5 / GPIO18 |
| 12V 水泵 / COB 补光灯 | 执行动作（浇水 / 补光） | 经继电器 |
| SH1106 OLED | 三页状态屏 | I2C：SDA21 / SCL22 |
| WS2812 灯条(11) | 状态+信号灯 | GPIO26 |
| ADC 模拟键盘(4键1脚) | 菜单操作 | GPIO33 |
| UART 三线 | 和树莓派通信 | TX17 / RX16 / **GND 共地** |

> **执行动作只有三种：浇水 water、补光 light、待机 idle。** 没有"施肥泵"（2026-05 已去掉营养泵）。

**2. 三个"为什么"（评委最爱问，务必真懂）**

- **为什么安全门（保命判断）放在 ESP32 本地、不放在树莓派/云？**
  → 深空场景有通信延迟，地面指令来不及救菜。**保命的判断必须在舱内本地完成**，上位机只提供"更聪明的建议"。这也对应我们故意不做"PC→ESP32 控制通道"——大屏是只读的。

- **为什么要三线共地（多一根 GND）？**
  → UART 靠电压高低传 0/1，两块板子必须有**共同的参考地**，否则电平判断错乱、乱码掉线。（我们真踩过：少接地线 → 一直掉线。）

- **三层保险各挡什么故障？**
  → ① 看门狗：程序卡死 → 3 秒自动重启；② 传感器失效：读数为空 → 用安全默认值，不乱动；③ 上位机离线：收不到建议 → 回退 ESP32 本地规则，继续照顾作物。

## 二、核心演示：拔 UART 线，展示离线自治

**动作分解（练到肌肉记忆）：**
1. 提示评委："我要拔掉和上位机的通信线了。"
2. 拔 UART 线 → 翻到 OLED 第三页 → 指 "PI:OFF"。
3. **停 2 秒**让评委看清，强调"浇水没停"。
4. 插回线，**等 3 秒**（等超时检测切回）→ 指 "PI:OK"。

**话术**（约 20 秒）：
> "现在演示离线自治。（拔线）看第三页，PI:OFF，上位机离线了——但本地规则接管，浇水不停。我造它时最在意这一点：人不在、网不在，菜也不能死。（插回）UART 恢复，PI:OK，重新采纳上位机建议。"

**⚠️ 屏幕没反应就说**："系统在检测中，看门狗 3 秒内会恢复。"（别慌，拖时间）

## 四、必答 Q&A（用自己的话，讲原理）

**Q：成本真的这么低？**
> "ESP32 侧大约 140 元，加树莓派约 400 元，整套约 540 元。用 Arduino 或纯树莓派方案会贵好几倍。"

**Q：ESP32 会不会死机？稳定吗？**
> "有三层保险：看门狗 3 秒自动重启、传感器失效切安全值、上位机离线回退本地规则。实机验收和 199 个测试都通过，可以长期运行。"

**Q：为什么保命判断不交给更聪明的 AI？**
> "因为深空有延迟，AI 和地面都可能不在线。保命的事必须舱内本地就能做，AI 只负责给更好的建议——这就是我们'两层决策'的底层逻辑。"

**Q：这些是你自己做的吗？**（诚实答）
> "硬件接线、固件在设备上的调试和这个离线演示是我主要负责的；AI 和视觉是队友负责，我们一起联调。"
