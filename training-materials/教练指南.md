# 教练指南 · 3 人战队（智能花盆 · 产品发明版）

> **对象**：3 名队员 · **发明/展示类**科创比赛
> **一句话定位**：这一版是**纯产品发明介绍**——讲"花为什么总被养死 → 我们做了一只会自己养花的开放式智能花盆"，**不扮演角色、不讲太空育种**。要求队员**真懂原理、能扛追问、能把事故变高光。**

## 2. 每个人必须"真懂"的原理清单（这版的灵魂）

> 验收方式：教练问"**为什么**"，学生用自己的话讲因果，不许背。讲不出因果 = 没过关。

**队员1（产品）**
- 三大养花痛点 + 三代花盆进化，讲得出画面感。
- "开放式"为什么比密闭一体机好？→ 谁都会用 + 储水省水。
- 和普通智能花盆的三点区别：断网还能养 / 会看长势 / 开放式储水。
- **"模型库为什么是蔬菜"**——诚信题，如实答 + 讲清养护逻辑通用。

**队员2（AI 养护系统）**
- **两层决策为什么能降级**：AI 给建议（树莓派问 DeepSeek）→ ESP32 拍板；AI 不在，本地规则接住。
- 为什么让 **ESP32 不联网**、网络全交给树莓派？→ 省内存、避免 OOM（真踩过的坑）。
- 摄像头**三重隔离** + 为什么"**眼睛只看不动手**"（AI 会看错，安全门在 ESP32）。
- 大屏是**只读遥测**，PC 不能反向控制花盆。

**队员3（机械结构与水循环）**
- **储水循环怎么回收水**：浇水→穿过土壤→回流储水箱→水泵复用，一滴不浪费。
- **安全护栏为什么能防淹根**：单次时长上限 + 每小时限频 + 最小间隔 + 高温跳过。
- UART 为什么要**共地**（三线交叉 + GND），少一根地线为什么会乱码。
- 三层保险各挡什么故障（看门狗 / 传感器失效切安全值 / 上位机离线回退本地）。

## 3. 集训节奏（10–12 次课，默认 10 次）

> **逐次课程表见 [集训课程表.md]**。下面是四个阶段的说明。

**第 1 周 · 全员奠基**
- 统一产品故事线（人人倒背）：*"花总被养死 → 我们做了一只会自己感知、思考、动手、断网也能养的开放式智能花盆。"*
- 每人练三层电梯陈述：**15 秒 / 30 秒 / 3 分钟**。
- 全员通读整机，能画出"传感器 → 两层决策 → 执行器 + 储水循环 + 旁路摄像头"这张大图。

**第 2 周 · 分工深耕**
- 各自吃透第 2 节自己的"真懂清单"，产出①讲解脚本 ②自己的 3–5 个必答题。
- **互相当学生讲一遍**：讲不清的地方就是漏洞。

**第 3 周 · 合练**
- 完整走位彩排；**现场 demo 至少完整跑通 3 次并计时**（目标 3:30）。
- 建立故障回退预案（见第 4 节）；模拟评委提问，**全程录像回看**。

**赛前一周 · 抗压打磨**
- 找一位队员不熟的老师当"恶评委"做高压模拟答辩（重点练"蔬菜模型库"和"和普通花盆区别"两题）。
- 物料终检；心态与临场。

## 4. 现场演示可靠性预案（重点，别跳过）

本系统真有 WiFi 掉线、OOM、继电器 brownout 的历史。展示类现场网络电源都不可控，**硬 demo 翻车是头号丢分点**。规则只有一条：**演示绝不吊死在单一脆弱环节上。**

- **L1 现场全链路 live**（最佳）：传感器 → ESP32 → 树莓派 → AI → 大屏，全跑通。
- **L2 断网 / 云 API 超时** → 切"ESP32 本地自主模式"+ 本地大屏。**这不是掉链子，恰恰是核心卖点**——当场说："看，断网了它照样在养花，人不在网不在，花也不能死。" 把事故变高光。
- **L3 硬件抽风** → 切预录运行视频/录屏，**但必须明说"这是我们上周的真实运行记录"**，绝不假装现场。

**⚠️ 摄像头演示的两个特殊约束（教练必须知道）：**
1. 视觉是**光照达标 + 距上次满 2 小时**才自动拍照——展台上等不了 2 小时。**做法**：比赛当天早上先手动跑一次真实采集，把真图和长势结论**预载到大屏视觉面板**，现场讲管线与逻辑；想证明"真会拍照"，可现场手动触发一次，并**如实说明是手动触发**。
2. **大屏视觉面板只有 dashboard 跑在树莓派上（和摄像头同机）时才有数据**。所以**演示当天让 `dashboard_server` 直接跑在树莓派上**，否则视觉区会显示"离线"。队员2 务必提前在树莓派上开好大屏。

## 5. 答辩提问训练（提前把杀手问题喂给他们）

用自己的话答，不许背：

- **"和市面上的智能花盆有啥不同？"** → 断网还能养 + 会看长势不只会浇 + 开放式储水省水。
- **"说是养花，模型库怎么是蔬菜？"** → 如实答：当前是 8 种蔬菜（长得快、阶段分明、便于验证），养护逻辑对花通用，换套参数即可。**别露怯、别假装是花。**
- **"AI 判错了怎么办？"** → 摄像头只建议不控制，真正的安全门在 ESP32 本地，AI 碰不到执行器。
- **"断网了还能养吗？"** → 能，本地自主，这就是我们最在意的设计。
- **"浇太多会不会淹死？"** → 有安全上限：单次时长/每小时限频/最小间隔/高温跳过。
- **"这里面哪些是你亲手做的？"** → 每人诚实指出自己的贡献（**别包揽**，诚信分）。

这几条答好，评委立刻判定"这队学生真懂"。

## 6. 诚信红线（展示类雷区，守住是加分）

- **不伪造 demo、不摆拍假硬件镜头**；预录内容必须明说是录像。
- **模型库是蔬菜就说蔬菜**，不假装是花——如实说明选蔬菜的理由和养护逻辑的通用性，反而加诚信分。
- **如实区分实拍与图形动画**——主动跟评委说哪段实拍、哪段是我们做的图形演示。
- 摄像头长势结论只当"参考/提示"，不吹"AI 一定判得准"。
