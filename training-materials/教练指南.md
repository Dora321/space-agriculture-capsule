# 教练指南 · 4人初高中战队（理解优先版）

> **对象**：4 名初高中生 · **展示类**科创比赛（《2035年的我》主题）
> **一句话定位**：这一版和旧的小学生版**根本不同**——旧版"不追求理解，能背能演就行"；**新版要求队员真懂原理、能扛追问、能把事故变高光。**

---

## 0. 为什么推倒重做（教练先读这段）

| | 旧版（3 名小学生） | 新版（4 名初高中生） |
|---|---|---|
| 目标 | 能背能演示 | **理解优先**：知其所以然 |
| 评委风险 | — | 会试探"是不是老师做的、学生懂不懂"，**答不出原理直接丢分** |
| 人数 | 3 | **4**（新增摄像头视觉+AI表型初筛，独立成第 4 支柱） |
| 演示 | 背台词 | 讲原理 + 现场应变 + **把断网/故障讲成卖点** |

**3→4 人的真实理由**：今年新增了 Camera Module 3 摄像头 + AI 早期表型初筛，这是一整块全新的工作（视觉采集 → 质量门 → 云端多模态 → 对照初筛），值得一个人专门吃透，而不是塞给原来的软件岗。人数从 3 变 4 是**有工作量支撑的**，评委问起来站得住。

## 2. 每个人必须"真懂"的原理清单（这版的灵魂）

> 验收方式：教练问"**为什么**"，学生用自己的话讲出因果，不许背。讲不出因果 = 没过关。

**队员1（舱体）**
- 为什么**安全门放在 ESP32 本地、不放在云/树莓派**？→ 深空有通信延迟，指令来不及救菜，保命判断必须在舱内。
- 看门狗、传感器失效切安全值、Pi 离线回退本地规则——**三层保险各挡什么**。
- UART 为什么要**共地**（三线交叉 + GND），少一根地线为什么会乱码。

**队员2（智能系统）**
- **两层决策为什么能降级**：AI 给建议（树莓派问 DeepSeek）→ ESP32 拍板；AI 不在，本地规则接住。
- 为什么让 **ESP32 不联网**、把网络全交给树莓派？→ 省内存、避免 OOM、更稳定（这是我们真踩过的坑）。
- 大屏是**只读遥测**：PC 不能反向控制 ESP32（对应"深空延迟"叙事，故意不做控制通道）。

**队员3（视觉/科学）** ← 今年新支柱，最容易被评委深挖
- 为什么摄像头由**树莓派独占**、ESP32 不碰？→ 相机吃内存/算力，隔离开互不拖累。
- **三重隔离**：相机隔离（只有视觉进程开摄像头）、网络隔离（API 超时不阻塞 UART）、控制隔离（视觉结论**只建议、不碰水泵补光灯**）。
- 为什么"**眼睛不控制手**"？→ AI 看错了也不会误浇水误开灯，安全门永远在 ESP32。
- **科学诚实三条**（差异化关键）：① n 按**独立种植周期**算，同一株拍很多张照片**不算多个样本**；② 结论分 **A/B/C/D/证据不足**级；③ 系统只产出"**待复筛候选**"，绝不说"我们育出了新品种"。

**队员4（指挥/立意）**
- 育种史主线：**人类一直在缩短育种反馈周期**（驯化一万年 → 杂交 13 年 → 基因编辑几个月 → 太空诱变但要回地面再种 5–8 代）。
- 我们的项目在这条线的位置：让**种植与初筛发生在舱内**，把反馈周期再砍一个量级。
- 温情落点：**育种人的奉献**（接袁隆平的棒），不是"太空里吃口热菜"。

## 3. 集训节奏（10–15 次课，默认 12 次）

> **逐次课程表见 [集训课程表.md]**——每次课练什么、谁验收什么、怎么压到 10 次或扩到 15 次，都在那份表里。下面是四个阶段的说明。

**第 1 周 · 全员奠基**
- 统一故事线（人人倒背）：*"2035 年火星/月宫基地，通信有几分钟延迟，地面指令来不及救菜——所以育种舱必须自己看、自己想、自己决定，人只做复核。"*
- 每人练三层电梯陈述：**15 秒 / 30 秒 / 3 分钟**。
- 全员通读整机，能画出"传感器 → 两层决策 → 执行器 + 旁路的视觉初筛"这张大图。

**第 2 周 · 分工深耕**
- 各自吃透第 2 节自己的"真懂清单"，产出①讲解脚本 ②自己的 3–5 个必答题。
- **互相当学生讲一遍**：队员1 给队员3 讲硬件、队员3 给队员1 讲视觉——讲不清的地方就是漏洞。

**第 3 周 · 合练**
- 完整走位彩排；**现场 demo 至少完整跑通 3 次并计时**（目标 4 分钟）。
- 建立故障回退预案（见第 4 节）；开始模拟评委提问，**全程录像回看**。

**赛前一周 · 抗压打磨**
- 找一位队员不熟的老师当"恶评委"做高压模拟答辩。
- 极端提问专练（第 5 节）；物料终检；心态与临场。

## 4. 现场演示可靠性预案（重点，别跳过）

本系统真有 WiFi 掉线、OOM、继电器 brownout 的历史。展示类现场网络电源都不可控，**硬 demo 翻车是头号丢分点**。规则只有一条：**演示绝不吊死在单一脆弱环节上。**

- **L1 现场全链路 live**（最佳）：传感器 → ESP32 → 树莓派 → AI → 大屏，全跑通。
- **L2 断网 / 云 API 超时** → 切"ESP32 本地自主模式"+ 本地大屏。**这不是掉链子，恰恰是核心卖点**——当场对评委说："看，断网了它照样在管菜，这就是深空自主。" 把事故变高光。
- **L3 硬件抽风** → 切预录运行视频/录屏，**但必须明说"这是我们上周的真实运行记录"**，绝不假装现场。

**⚠️ 摄像头演示的两个特殊约束（教练必须知道）：**
1. 视觉是**光照达标 + 距上次满 2 小时**才自动拍照——展台上等不了 2 小时。**做法**：比赛当天早上先手动跑一次真实采集（`py tools/vision_service.py capture ...` 或对着植株拍一张真实图），把真图和初筛结论**预载到大屏视觉面板**，现场讲管线与逻辑；想证明"真会拍照"，可现场手动触发一次，并**如实说明这是手动触发**。
2. **大屏的视觉面板目前只有在 dashboard 跑在树莓派上（和摄像头同机）时才有数据**（云端上传通路还没实现）。所以**演示当天让 `dashboard_server` 直接跑在树莓派上**，否则视觉区会显示"离线"。队员2/队员3 务必提前在树莓派上开好大屏。

## 5. 答辩提问训练（提前把杀手问题喂给他们）

用自己的话答，不许背：

- **"这里面哪些是你亲手做的？"** → 每人诚实指出自己的贡献（**别包揽**，诚信分）。
- **"AI 判错了怎么办？"** → 视觉只建议不控制，真正的安全门在 ESP32 本地，AI 碰不到执行器。
- **"和市面上的智能花盆/买的套件有啥不同？"** → 双层自主 + 科学筛选的诚实性。
- **"你的数据可信吗？样本够吗？"** → n 按独立种植周期算不是照片张数，结论分 A/B/C/D 级，我们只敢说"待复筛候选"。
- **"断网了系统还能活吗？"** → 能，本地自主，这就是为深空场景设计的。
- **"摄像头为什么不直接控制浇水？"** → 眼睛只看不动手；看错了也不会误动执行器。

这几条答好，评委立刻判定"这队学生真懂"。

## 6. 诚信红线（展示类雷区，守住是加分）

- **不伪造 demo、不摆拍假硬件镜头**；预录内容必须明说是录像。
- **不用 AI 生成袁隆平等真人肖像**。
- **如实区分实拍与图形动画**——主动跟评委说"这段实拍、这段是我们做的图形演示"，反而加诚信分。
- 视觉结论对外一律叫"**待复筛候选**"，不吹"新品种/已证明更优"。
