## 一、你负责的系统（原理速通 · 要能讲因果）

**1. 硬件都有什么，各干什么**

| 零件 | 作用 | 接在哪 |
|---|---|---|
| ESP32 | 养护控制器（本地决策 + 控制执行器） | 主控 |
| 土壤湿度传感器 | 测土干湿 | GPIO34（ADC） |
| DHT11 | 测环境温湿度 | GPIO4 |
| 继电器×2 | 电子开关，控水泵 / 补光灯 | GPIO5 / GPIO18 |
| 12V 水泵 / COB 补光灯 | 执行动作（浇水 / 补光） | 经继电器 |
| 储水箱 + 回水管 | 灌溉水回收循环 | 盆体下方 |
| SH1106 OLED | 三页状态屏 | I2C：SDA21 / SCL22 |
| WS2812 灯条(11) | 状态 + 信号灯 | GPIO26 |
| 四键模拟按键(4键1脚) | 菜单/切换植物 | GPIO33 |
| UART 三线 | 和树莓派通信 | TX17 / RX16 / **GND 共地** |

> **执行动作只有三种：浇水 water、补光 light、待机 idle。** 没有"施肥泵"（2026-05 已去掉营养泵）。

**2. 开放式 + 储水循环（你的招牌，务必讲清）**
- 市面多是**密闭一体机**：水浇下去就流走浪费了。
- 我们是**开放式**：花盆是熟悉的样子，谁都会用。
- **储水循环**：浇下去的水穿过土壤，多余的**回流储水箱**，水泵再从储水箱抽水复用——**浇下去的水一滴不浪费**，缺水地区、长期没人添水时特别有用。

**3. 安全护栏（浇水不会淹死根）**
- 水泵单次最长 60 秒、补光灯最长 120 秒、每小时最多 12 次动作、两次动作有最小间隔。
- 温度异常时跳过浇水（高温闷根、低温不动手）。

**4. 三层保险各挡什么故障？**
- ① 看门狗：程序卡死 → 3 秒自动重启；② 传感器失效：读数为空 → 用安全默认值，不乱动；③ 上位机离线：收不到建议 → 回退本地规则，继续养护。

**5. 成本**
- 单盆核心约 **¥135**（ESP32 侧）；加树莓派约 400 元、由多盆共享分摊（一拖 N）。摄像头模块另计。

## 二、核心演示：浇水 + 储水循环

**动作分解（练到肌肉记忆）：**
1. 指盆体储水箱，讲"水回流复用"。
2. 捏住土壤传感器（模拟干燥）→ 水泵启动 → 水从储水箱抽上来 → 多余水回流。
3. 强调安全上限："单次最长 60 秒、每小时最多 12 次，绝不淹根。"

**话术**（约 50 秒）：
> "我负责花盆的身体。市面很多智能花盆是密闭一体机，水浇下去就浪费了。我们做开放式——花盆是熟悉的样子谁都会用。关键在这个储水箱：浇下去的水穿过土壤，多余的回流储水箱，水泵再抽上来循环用，一滴不浪费。整套核心只要 135 元。我演示一次浇水——（捏传感器）它判断土干了，水泵启动，多余的水又流回去；它还有安全上限，绝不会把根淹死。"

**⚠️ 水泵没动就说**："系统在做安全检查，看门狗 3 秒内会恢复。"（别慌，拖时间）

## 三、必答 Q&A（用自己的话，讲原理）

**Q：成本真的这么低？**
> "单盆核心约 135 元。树莓派约 400 元，但由多盆共享分摊，一拖 N，不是每盆一台。用 Arduino 或纯树莓派方案会贵好几倍。"

**Q：储水循环怎么回收水？**
> "开放盆体下方是储水箱，浇的水穿过土壤后回流储水箱，水泵从储水箱抽水循环用。配合精量滴灌和安全上限，既不淹根也不浪费。"

**Q：ESP32 会不会死机？稳定吗？**
> "有三层保险：看门狗 3 秒自动重启、传感器失效切安全值、上位机离线回退本地规则。实机验收和 199 个测试都通过，可以长期运行。"

**Q：浇太多会不会淹死植物？**
> "不会。水泵单次最长 60 秒、每小时最多 12 次、两次动作有最小间隔，高温还会跳过浇水。安全上限写死在固件里，AI 建议也要过这道护栏。"
